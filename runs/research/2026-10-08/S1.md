## Por qué

Hoy el store de este repo pesa 22 MB en objetos + 5,8 MB de log por 443 KB de desk. Causas medidas
(`14 §10`): una transacción por documento (540), el índice mmap persistido y versionado por cada
transacción (55 %), el plan resuelto guardado dos veces (CAS y línea del log, 25 % + log), un tree
object por posición, el texto guardado cuatro veces (nodos, copia verbatim `source-node`, plan, log).
Principio del 14: canónico ≠ persistido. El parse es determinista: se verifica, no se guarda.

## Qué hacer (en este orden; cada paso con suite verde antes del siguiente)

1. **Sin copia verbatim.** Eliminar `source-node` y su arista `derived root→source`
   (`src/kimun/surface/docs.cljc` `binding-ops`). OJO: la rama A1 (ya en main) guarda el
   `:contract` (id del descriptor con que se extrajo) en la evidencia de ESA arista. Muévelo a la
   arista `reference root→external` (el anchor del archivo) y, para documentos sin archivo
   (`docs create` sin path), a la arista `reference root→modelo`. Todo lector de `:contract`
   (`payload-of`, `document`, `fields`, `sections`, índice, `edges`, `diagnostics`) debe seguir
   funcionando; los tests de A1 (`typed_docs_test`, `optional_field_hash_test`, `index/build_test`,
   `http/documents_test`) son la regresión. El texto original de un documento se obtiene del
   archivo vía el anchor; si no hay archivo (`:inline`, punto 3), del árbol (`store->markdown`).
2. **El árbol del documento es caché.** Los nodos `block`/`text`/`opaque` y los tree objects de
   un documento con anchor externo NO se escriben al CAS: se persisten el descriptor (con el root
   hash = merkle-root) y el anchor. Al abrir, un documento se reconstruye desde el archivo
   (`ast/parse` + `ast->plan`/`collect`) bajo demanda y se verifica `merkle-root == root hash
   registrado`; si el fingerprint del anchor no coincide con el archivo, el documento está
   `stale` (ya existe el concepto en `stores check`/`status`). Posiciones y nodos **referenciados
   por alguna arista** (hechos, spans, `reference`/`derived` desde otros documentos) sí se
   persisten (regla de los spans, `atom-stand-off-addresses-are-virtual-until-referenced`).
   Implementación sugerida: un caché por cabecera en memoria `{tree-id → {:nodes :tree}}`
   poblado perezosamente por un resolver en `kimun.surface.docs`; el kernel no hace I/O (anillo 0),
   así que el resolver vive en superficie/host y se inyecta como `load`.
3. **`inline` por caso.** `store.edn :content :by-reference|:inline` (default by-reference) y
   override por documento (`docs track --inline`): con inline, nodos y tree objects sí se
   persisten (comportamiento actual). Caso de uso declarado: páginas web que cambian.
4. **Una revisión por `build`.** `include build` compone UN `TransactionPlan` con todos los
